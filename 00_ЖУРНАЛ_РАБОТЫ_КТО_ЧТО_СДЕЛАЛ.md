## С чего продолжать

Порядок — по важности. Взяли задачу — допишите `← Имя, дата`.

**Бизнес (без них настоящих денег не будет):**
1. Юрист: какая модель работы (агент оператора ПВТ или своё юрлицо), вопросы — `07_ПЛАН_ЗАПУСКА…`, раздел 3.4.
2. Встреча с Whitebird (запасные: Bynex, Dzengi): договор и песочница API. Питч — `08_ПИТЧ…`.
3. Заявка в bePaid на эквайринг с регулярными списаниями по сохранённой карте.
4. Интервью с 10–15 будущими пользователями: сколько готовы откладывать, что пугает, нужны ли акции.

**Техника:**
5. Арендовать тестовый сервер в РБ (2 vCPU / 4 ГБ / 40–60 ГБ, Ubuntu 24.04), домен, развернуть по `deploy/` с паролем (`Caddyfile.staging`).
6. Telegram-бот (токен от @BotFather) и почта (SMTP) — для уведомлений и подтверждения почты.
7. После получения API оператора — модуль `WhitebirdBroker` в `internal/engine` (оценка 3–4 недели).
8. Toncoin (TON) с 30.06.2026 не торгуется на Binance (статус BREAK), Bybit его не поддерживает. Текущая цена уже
   берётся из CoinGecko, но история свечей (графики, «машина времени») по TON обрывается в июне: решить — убрать TON
   из плана «Максимум» или подключить источник истории (CoinGecko market_chart / OKX).
9. Если акции США остаются — лицензированный источник котировок вместо Yahoo Finance.
10. Официальные логотипы банков (из их бренд-материалов) — в `web/app/public/banks/`; в бою проверить, что bePaid
    присылает `issuer_name`, и решить, нужен ли платный BIN-справочник вместо binlist.net.
11. Токены компаний РБ пока учебная модель с условной ставкой — заменить на реальные выпуски площадки-партнёра.
    Плана «Беларусь» больше нет, поэтому сейчас токены РБ попадают в копилку только через «Свой состав» (Pro).
12. Проверка личности: договор с ЕРИП на подключение к МСИ (правила и тестовый стенд — raschet.by, OAuth),
    после него сверить названия полей ответа в `internal/kyc` (`fromClaims`) со спецификацией оператора.
    Для паспорта и селфи — договор с Sumsub (или аналогом), ключи в `.env` (`SUMSUB_*`), вебхук `/api/v1/webhooks/sumsub`.
13. Google OAuth (проект в Google Cloud у напарника): в клиенте добавить Authorized redirect URIs
    `http://localhost:8090/oauth/google/callback` (+ боевой домен позже), в Audience — тестовых пользователей (свои gmail);
    перед запуском — опубликовать приложение (Publish app). SMTP для писем с кодом регистрации. Apple ID — позже.

## Как работать вдвоём через GitHub

```bash
git clone https://github.com/alxtchshv/autoinvest-by.git   # один раз
cd autoinvest-by
make test-stand                                            # Windows: test_stand.bat
```

Каждый раз:
```bash
git pull                     # забрать изменения напарника
# ...работаем...
git add -A && git commit -m "Коротко, что сделано"
git push
```

- Крупную или рискованную задачу делайте в отдельной ветке (`git switch -c feature/название`) и открывайте Pull Request —
  второй посмотрит перед слиянием.
- Если `git pull` пишет о конфликте — не удаляйте чужое, откройте файл, оставьте обе правки и закоммитьте.
- Не коммитьте `.env`, базы `data/` и `data-test/` — они уже в `.gitignore`.
