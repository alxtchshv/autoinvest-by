## 2. Что уже работает (коротко)

- **Сайт и кабинет:** лендинг с «машиной времени» на реальных ценах, калькулятор, копилки с расписанием и целями, 6 готовых планов + свой состав (Pro), рынок, операции и выписки, чеки, тарифы Pro, рефералы.
- **Вход:** регистрация с кодом на почту; вход по почте/телефону + пароль; Google (ключи есть); вход по коду в Telegram;
  вторая защита — Google Authenticator и Face ID / Touch ID / отпечаток (WebAuthn, вместо кода); подтверждение опасных действий.
- **Telegram-бот @AutoInvestAgent:** привязка аккаунта, меню кнопками (баланс, копилки, пауза, операции, уведомления), коды входа,
  подтверждение телефона кнопкой «Поделиться номером», вопросы в поддержку и ответы из группы AutoInvestTeam, журнал всей переписки.
- **Поддержка:** обращения на сайте и из бота, ответы сотрудников в админке или reply в группе Telegram.
- **Проверка личности:** путь «МСИ (через банк)» и «паспорт + селфи (Sumsub)» — код готов, без договоров работает в тестовом режиме;
  в боевом режиме без ключей — ручная проверка анкеты сотрудником.
- **Админка:** обзор и метрики для партнёров, пользователи (выгрузки операций/переписки/журнала файлами), верификация,
  поддержка, операции (на экране — только требующие действия, история — CSV), состояние источников котировок.

## 3. Что ещё НЕ готово (и почему нельзя «с реальными деньгами»)

| № | Что | Почему не готово | Что нужно |
| :- | :--- | :--- | :--- |
| 1 | **Покупка активов у партнёра** (`WhitebirdBroker` в `internal/engine/engine.go`) | Публичного API нет, спецификацию даёт оператор после договора. Сейчас покупки «учебные» (`BROKER=paper`): по реальным ценам, но без реальной покупки. | Договор с Whitebird (или Bynex/Dzengi), их API, ~3–4 недели работы. |
| 2 | **Боевые списания с карт** | Нужен договор bePaid на интернет-эквайринг с рекуррентными платежами. Код bePaid готов (`internal/payments/bepaid.go`). | Заявка в bePaid. До этого — тестовый магазин bePaid (`BEPAID_TEST=true`). |
| 3 | Защита от главной ошибки | `PAYMENTS=bepaid BEPAID_TEST=false` вместе с `BROKER=paper` **запрещено в коде** — иначе мы брали бы деньги и ничего не покупали. | Включится само, когда будет пункт 1. |
| 4 | МСИ и Sumsub | Нужны договоры с ЕРИП (МСИ) и Sumsub. | Ключи в `.env` (`MSI_*`, `SUMSUB_*`). |
| 5 | Письма (код регистрации, уведомления) | Нужен SMTP. **В боевом режиме без SMTP регистрация закрыта** — код некуда отправить. | Ящик Яндекс 360 / Gmail с паролем приложения → `SMTP_*`. |
| 6 | Apple ID | Платный аккаунт разработчика (99 $/год). Код готов, выключен. | Позже. |
| 7 | Токены компаний РБ | Учебная модель с условной ставкой. | Реальные выпуски партнёра. |
| 8 | История цены TON, акции США | TON не торгуется на Binance с 30.06.2026; котировки акций — из Yahoo (без лицензии). | Решить: убрать или подключить лицензированный источник. |
| 9 | Юридическое | Модель работы (агент оператора ПВТ или своё юрлицо), оферта и политика — проекты. | Юрист, см. `07_ПЛАН_ЗАПУСКА…`, раздел 3.4. |

**Вывод для теста «вдвоём с реальными деньгами»:** реальные деньги станут возможны только после пунктов 1–2. Сейчас на тестовом сервере
можно честно проверить всё остальное: вход, бота, поддержку, копилки, расписание, выводы — на тестовых картах.

## 5. Деплой тестового сервера — по шагам

### 5.1. Что нужно
- **VPS:** Ubuntu 24.04, 2 vCPU / 4 ГБ RAM / 40–60 ГБ SSD. **Лучше в Беларуси** (becloud, hoster.by и т. п.):
  сайт НБРБ (официальный курс) из-за границы часто недоступен — без курса сервис не покупает; плюс требования к размещению данных граждан РБ.
- **Домен** и поддомен для теста, например `test.autoinvest.by` — A-запись на IP сервера.
- Открытые порты 80 и 443.

### 5.2. Установка (≈15 минут)
```bash
# на сервере, под пользователем с sudo
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker
git clone https://github.com/alxtchshv/autoinvest-by.git /opt/autoinvest && cd /opt/autoinvest
cp .env.example .env && nano .env          # заполнить по 5.3
cp deploy/Caddyfile.staging deploy/Caddyfile && nano deploy/Caddyfile   # домен + пароль (5.4)
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml logs -f app                  # ждём «AutoInvest запущен»
```
Проверка: `https://test.ваш-домен/healthz` → `ok`; `/readyz` → `ok`, когда загрузились котировки и курс НБРБ.

### 5.3. `.env` для тестового сервера (минимум)
```ini
APP_ENV=production                 # боевые правила безопасности: 2FA для админки, https-cookie, без тестовых режимов
PUBLIC_URL=https://test.ваш-домен
ADMIN_EMAIL=you@mail.by
ADMIN_PASSWORD=длинный-пароль       # админ создаётся при старте; в админку пустит только после включения Google Authenticator
PAYMENTS=sandbox                   # тестовая платёжка внутри сервиса; или PAYMENTS=bepaid + BEPAID_TEST=true + ключи тестового магазина
BROKER=paper                       # учебные покупки по реальным ценам (боевого брокера пока нет)
MARKET=live
SMTP_HOST=smtp.yandex.ru           # без SMTP регистрация в production закрыта
SMTP_PORT=465
SMTP_USER=noreply@ваш-домен
SMTP_PASSWORD=пароль-приложения
SMTP_FROM=AutoInvest <noreply@ваш-домен>
TELEGRAM_BOT_TOKEN=…               # и убрать его с Mac напарника (раздел 4)
TELEGRAM_SUPPORT_CHAT_ID=-5446665739
GOOGLE_CLIENT_ID=…
GOOGLE_CLIENT_SECRET=…
KYC_DOCS=manual                    # без договоров — анкета, проверяет сотрудник в админке
MSI_MODE=off
```
Остальные параметры и комментарии — в `.env.example`.

### 5.4. Пароль на тестовый контур
Тест закрыт Basic-авторизацией (вебхуки bePaid проходят без неё — у них своя подпись):
```bash
docker run --rm caddy:2-alpine caddy hash-password --plaintext 'пароль-для-входа-на-тест'
```
Хеш вставить в `deploy/Caddyfile` вместо `REPLACE_WITH_HASH` (логин — `tester`), затем `docker compose … up -d`.

### 5.5. После первого запуска
1. **Google:** Google Cloud → Google Auth Platform → Clients → клиент → Authorized redirect URIs → добавить
   `https://test.ваш-домен/oauth/google/callback`. В Audience → Test users — почты всех, кто тестирует.
2. **Telegram:** бот сам выставит описание и команды. Аватарка — вручную, `docs/brand/telegram-avatar.png` → @BotFather `/setuserpic`.
3. **bePaid (если тестовый магазин):** в кабинете bePaid адрес уведомлений `https://test.ваш-домен/api/v1/webhooks/bepaid`.
4. **Админ:** войти, Профиль → Безопасность → включить Google Authenticator, затем открыть `/admin`.
5. **Бэкапы** (раз в час, cron на сервере):
   ```bash
   crontab -e
   0 * * * * cd /opt/autoinvest && BACKUP_DOCKER=1 BACKUP_DIR=/opt/autoinvest/backups ./scripts/backup.sh >> /var/log/autoinvest-backup.log 2>&1
   ```
   24 часовые и 30 дневных копий хранятся в `/opt/autoinvest/backups`. Для копии вне сервера — переменные `RESTIC_*` (описаны в `scripts/backup.sh`).
   Восстановление: остановить `app`, положить копию на место `autoinvest.db` в томе, запустить.

### 5.6. Обновление и откат
```bash
cd /opt/autoinvest && git pull && docker compose -f deploy/docker-compose.yml up -d --build
# откат: git checkout <прошлый коммит> && docker compose … up -d --build  (миграции только добавляют, данные не теряются)
```

## 6. Проверка безопасности (07.11.2026)

**Автоматические проверки**
- `govulncheck`: **0 уязвимостей в используемом коде**. Обновлены `golang.org/x/crypto`, `golang.org/x/sys`, `golang-jwt/jwt`;
  сборка — Go 1.26.10 (`toolchain` в `go.mod`, образ `golang:1.26-alpine`).
- `npm audit --omit=dev`: 0 уязвимостей. `go vet` — чисто. Секретов в истории git нет (`.env` в `.gitignore` и `.dockerignore`).

**Что уже защищено**
- Пароли — PBKDF2-SHA256, 600 000 итераций; сессии — случайный токен, в базе хеш; cookie `HttpOnly`, `SameSite=Lax`, `Secure` на https.
- CSRF (double-submit) на всех изменяющих запросах; CSP, HSTS, `frame-ancestors 'none'`; ограничение частоты на вход, коды, регистрацию.
- Вторая защита (TOTP / WebAuthn) при входе и перед выводом денег, закрытием копилки, сменой пароля, удалением аккаунта.
- Админка: только роли admin/support, в production — только с включённой 2FA; выгрузки данных сотрудниками пишутся в журнал клиента.
- Вебхуки: bePaid — Basic-авторизация + RSA-подпись (если задан ключ), Sumsub — HMAC; OAuth — одноразовый state + привязка к браузеру.
- Коды входа и ссылки привязки не попадают в журнал переписки; файлы KYC — права 0600, только для сотрудника.
- Запрет боевых списаний без настоящего брокера; тестовые режимы (sandbox) запрещены при `APP_ENV=production`.

**Сделать до боевых денег**
1. Перевыпустить токен бота и секрет Google (они были в переписке).
2. Внешний пентест (OWASP Top 10) и проверка юристом политик.
3. Бэкапы вне сервера (restic) + проверка восстановления.
4. Мониторинг: `/readyz`, алерты в группу Telegram при сбое курса или платежей.
5. Ограничение доступа к серверу: SSH только по ключу, firewall (ufw: 22, 80, 443).

## 7. Ручные тесты на тестовом сервере (для Руслана)

Подробные сценарии для локального стенда — `ТЕСТИРОВАНИЕ_ВРУЧНУЮ.md`. На сервере пройдите по порядку:

1. **Регистрация:** новая почта → код из письма → аккаунт создан, анкета-подбор плана открылась.
2. **Вход:** выйти → «Почта или телефон» + пароль; менеджер паролей браузера предлагает сохранить и подставить пароль.
3. **Google:** «Продолжить с Google» (почта должна быть в Test users) → вход; с почтой существующего аккаунта — привязка к нему.
4. **Telegram:** Профиль → Уведомления → «Подключить Telegram» → в Telegram «Старт» → бот пишет «Аккаунт подключён». Кнопки меню работают.
5. **Телефон:** Безопасность → «Телефон и код в Telegram» → «Подтвердить» → в боте «Поделиться номером». Выйти → «Код в Telegram» → код пришёл в бот → вход.
6. **Вторая защита:** включить Google Authenticator → выйти/войти — просит код. Добавить Face ID / отпечаток → при входе с паролем — касание вместо кода.
   На другом устройстве без ключа — «Пришлём код в Telegram / на почту».
7. **Карта:** привязать тестовую карту (sandbox — номера на странице оплаты; bePaid test — карты из документации bePaid).
8. **Копилка:** создать с целью и датой → подсказка суммы → первое пополнение → чек; «Управление» → пауза/включение; смена плана.
9. **Вывод:** «Вывести» → подтверждение паролем + код (или касанием) → операция в «Операциях».
10. **Поддержка:** вопрос с сайта и из бота → приходят в группу AutoInvestTeam → ответить reply → ответ у клиента в боте (подробно, с номером) и на сайте → клиент отвечает reply в боте → сообщение в обращении.
11. **Админка:** пользователь → три выгрузки скачиваются и открываются в Excel; «Операции» → «Скачать операции» за период; в «Системе» источники зелёные.
12. **Мои данные:** Профиль → Безопасность → «Скачать мои данные» — в JSON есть переписка с ботом; «Личные данные» → «Скачать журнал».
13. **Телефон и Mac:** всё то же на iPhone/Android — меню, свёрнутое меню, модальные окна, Face ID.

## 8. Как работать вдвоём

- Перед работой: `git pull`, прочитать «С чего продолжать» в журнале. Крупная задача — своя ветка и Pull Request, CI должен быть зелёным.
- После работы: запись сверху в `00_ЖУРНАЛ…`, коммит, push.
- Секреты — только в `.env` (локально и на сервере), передавать через менеджер паролей (1Password / Bitwarden).
- Боты: @AutoInvestAgent — только на сервере; для разработки у каждого свой тестовый бот.
